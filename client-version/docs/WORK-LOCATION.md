# Work location and boundaries

The 13 October 2026 owner instruction adds geofencing for every signed-in member role. The new work-location feature is independent of the earlier full-edition territory module, customer evidence review and daily SR reconciliation.

Administrators and Operations Managers use **Work locations** to add a boundary. Choose the branch, search for the public worksite, enter the real coordinates or use **Drop pin**, then set the radius with the slider, presets or numeric field. A member inherits their branch boundary; **Assign boundary** selects an explicit worksite without changing branch or team-leader assignments. The individual-boundary control creates and assigns a personal circle atomically. Editing a personal circle never silently moves another member's shared boundary. Selecting a member or branch shows its assigned radius even when no live point has been recorded. Save real locations first, check member assignments, then enable **Outside boundary blocks work and sales**. Enforcement is initially disabled to avoid inventing branch coordinates or blocking existing accounts before setup. Unassigned members cannot start or capture when it is enabled. See the [step-by-step guide](QANAWAT-WORK-LOCATIONS-AND-SR-GUIDE.md).

Every member can open **Work location** and explicitly start or end their own session. Device permission and a real GPS reading are required to start tracking. Android and the mobile demo update while Qanawat is open and visible; hidden or closed apps stop collecting, and older positions are marked stale. The portal behaves the same way. A visible indicator links to the session controls. End work or sign out to stop local collection. Another device's session must be explicitly ended before starting here.

The server also checks capture and shift-start requests. An enabled boundary requires an active session and a point no older than 90 seconds. A known simulated point, missing location, accuracy over 100 metres, or an accuracy circle crossing the boundary cannot prove that the member is inside. A clear point outside the boundary is recorded but capture is blocked. This is device GPS evidence; it is not a guarantee against sophisticated location spoofing. Accepted OCR jobs finish even after a session ends; a new sale submission is checked again.

Administrators, Operations Managers and Sales Managers can view the authorized current workforce. Branch Managers see their current branch; team leaders see their explicitly designated current sales agents and themselves. Other roles see only their own locations. After reassignment, a new leader or branch manager cannot acquire the member's earlier assignment's GPS history. This is deliberately more restrictive than historical sales access. Database permission restrictions still apply to every route and client control.

Location CSV and Excel exports include member, recorded branch, point time, coordinates, accuracy, saved boundary center/radius and distance/state at recording. Filter by business dates, member, branch or a geographic radius chosen on the map. A report filter never changes enforcement boundaries. Coordinates and boundary snapshots are encrypted at rest. Point writes serialize per member with bounded contention; one active session per member is also protected by a database index. Exact point retries do not duplicate history. Default precise-location retention is 30 days, configurable from 1 to 365 using `WORK_LOCATION_RETENTION_DAYS`.

Street maps use [OpenFreeMap](https://openfreemap.org/) with required OpenMapTiles/OpenStreetMap attribution. MapLibre renders available building heights in 3D; coverage varies. The optional satellite overview uses EOX Sentinel-2 cloudless **2016**, commercially permitted under CC BY 4.0, with provider attribution, date and **10-metre** resolution displayed. It replaces the former cloudy 250-metre weather overview. It is not live/current or a building-level photograph. Free external [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started) open satellite or Street View at the selected worksite where coverage exists. No Google API key was added; embedding Google's map inside the application would require its Cloud setup. Use street maps or typed coordinates for precise branch boundaries. Map-provider availability never authorizes a capture; coordinates and radius controls remain usable when tiles fail.

Public-place search follows the [Nominatim usage policy](https://operations.osmfoundation.org/policies/nominatim/). It runs only on explicit public-place queries, never autocomplete or employee-coordinate reverse tracking, caches results and uses identifying request headers. PostgreSQL-backed workers share a rate lock, limiting aggregate external requests to one per 1.1 seconds. `MAP_SEARCH_URL` can select a compatible HTTPS provider without a client rebuild. The public service has no availability guarantee; its failure leaves the pin and coordinate controls available. Larger or heavier usage needs a private/contracted compatible provider.

Migration 020 adds only work-location tables and the new role grants. The release backs up deployment and database files first. If the API must roll back, retain the additive tables and restore the prior deployment/image; the old API ignores the new grants and the enforcement flag remains separate. Downgrade 020 removes its location history, so export any required new records before a deliberate downgrade. Upgrade, downgrade and re-upgrade are tested against a disposable PostgreSQL 019 schema with operational-record fingerprints preserved.

The mobile demo also renders an explicit unique `SAMPLE-SR-…` label in its synthetic order capture. The optional sample receipt uses the same SR for that order, including a resumed draft. OCR reads and binds the value to the image normally; production captures never invent an SR from a request ID.
